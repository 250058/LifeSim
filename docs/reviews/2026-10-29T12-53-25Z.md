# Claude 사용 한도와 검토 대기 운영 개정

2026-10-29 12:53 UTC 사용자 요청: “클로드에게 5시간 한도에 도달하면 언제 돌아오는지도 알려달라고 적어놔. 클로드 한도에 도달한 동안은 계속 리뷰 요청 찾는 거 중단해도 됨.”

[CLAUDE_REVIEW.md](../../CLAUDE_REVIEW.md)의 ‘5시간 사용 한도와 복귀 알림’ 절과 [CLAUDE.md](../../CLAUDE.md)에 인계 규칙을 추가한다.

- Claude는 한도 종류·확인 시각, 서비스의 한도 해제 날짜/시각/시간대, 실제 작업 재개 예정, 마지막 push SHA와 남은 작업을 이슈 #1에 남긴다. 알 수 없는 시각은 미정, 예상은 추정으로 구분한다. 한도 때문에 보낼 수 없으면 재개 직후 알린다.
- Codex는 확인된 한도 알림을 `state.json.claude_availability`에 저장하고 재개 기준까지 리뷰 요청 탐색을 쉬며 반복적인 변경 없음 보고를 만들지 않는다. 재개 기준은 실제 복귀 예정, 없으면 한도 해제 시각이다.
- 시각이 미정이면 기존 정기 회차에서 한도·복귀 알림만 최소 확인한다. 재개 시각 이후 기존 회차에서 정상 탐색을 다시 시작하며, 이 대화로 전달된 조기 재개·준비 요청은 즉시 처리한다.
- 기존 자동화의 시간 간격·시간대·활성 상태는 유지하고 프롬프트의 실행 첫 단계에 조건부 생략 규칙을 반영한다. 예약 자체의 일시정지나 새 댓글 이벤트 연결은 아니다.

현재 이슈 #1의 댓글 15개에서 한도 도달·복귀 시각 알림은 확인되지 않았다. 따라서 현재 한도 상태는 `unknown`, 탐색 보류는 `false`로 기록하며 지금 대기 중이라고 단정하지 않는다. 단순 무변경을 한도 증거로 쓰지 않는다.

이 변경은 운영 지침 개정이다. 게임 코드·제품 계획·검토 완료 SHA·기존 결함 판정은 바꾸지 않는다. 기준 main은 `214ac774730941cdea89cc7a6adc26f051734bef`이고 마지막 코드 검토는 [09:52 보고서](2026-10-29T09-52-10Z.md)의 `6a75264` 범위다. 게임 실행 검증은 하지 않는다. 문서 저장과 자동화 설정은 재읽기로 확인하고 이슈 #1과 사용자용 Page에 전달한다. Claude가 실제 읽고 알림 규칙을 적용했는지는 후속 응답으로 확인한다.
