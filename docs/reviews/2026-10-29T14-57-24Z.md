- 이는 Claude 4차 응답의 “구저장 종료값 충돌 시 기록 기준으로 복구”와 다르다. 출소가 이미 플레이된 경우와 앞으로 예정된 출소를 구분하지 않는 점도 남아 있다.
- 수정 방향: 선고 원기록·현재 집행·실제 출소 이력을 구분하고 버전 있는 이전 규칙을 둔다. 복구 가능한 잔여 기간은 기록에서 판단하며, 근거 없는 조기 출소/감형으로 과거 사실을 바꾸지 않는다. 이미 진행된 구저장의 충돌은 원기록 보존과 이전 사유를 남긴다.
- 완료 기준: 종료값 충돌 저장을 출소 전/후로 나누어 이전하고, 판결 원본·집행 상태·결격 시작점·저장 재개가 일치해야 한다. 법적 합산/병합의 상세 구현은 별도 제도 검증이 필요하다.

## 사용자 방향과 추가 구현 지침

이번 실제 등록은 사건 ID **4,526개**, 직업 정의 **20개**다. 새 사건은 산후 가족 계획과 치료 유지/중단 후속 등이며 직업 대폭 확대, 범죄·피해/기관/회복 확장, F-001 전체 사슬은 진행 중이다. 기존 묻지마폭행 카드나 이미 제안한 F-001~F-005를 새 제안으로 다시 세지 않는다.

일상 풀은 빈 후보의 몫을 다른 풀로 넘기지 않아 희귀 질환이 후보 부족 때문에 과도하게 나오는 문제가 완화됐다. 다만 꽉 찬 풀에서는 여전히 연간 표시 한 자리를 나누고, 만성 질환 시작·결혼·출산·실직처럼 장기 상태를 바꾸는 사건도 그 안에 있다([pools.ts](https://github.com/250058/LifeSim/blob/bae61c365b31ef5ac6b01a99cac04bce6fe9c177/src/engine/pools.ts#L31)). 콘텐츠 추가가 세계 발생률을 바꾸지 않도록 장기 상태 발생과 표시 표본을 분리하는 기존 계획은 계속 필요하다.

**새 제안 ID는 추가하지 않는다.** R-006의 실제 인물 소실을 근거로 기존 **F-002 교대와 돌봄 / F-004 학교 연락처**의 다음 교차 사례를 구체화한다.

| 요소 | 구현 지침 |
|---|---|
| 시나리오 | 헤어진 두 부모 중 한 명에게 갑작스러운 교대가 생겨, 아이 인계/학교 연락을 다른 보호자와 조정한다 |
| 조건 | 같은 childId, 유지된 두 parentId, 실제 보호 권한·연락 가능 여부, 돌봄 일정과 이동시간. 이별 자체는 인물 삭제나 친권 상실을 뜻하지 않는다 |
| 선택 | 요청·거절·연기·다른 보호자에게 제안·교대 거절. 상대 NPC의 동의 전에는 확정 일정으로 처리하지 않는다 |
| 상태 변화 | 제안/동의/취소, 실제 인계자와 기한, 교통·돌봄 비용의 지급자, 실제 수신 연락처를 원인 ID로 기록 |
| 후속 영향 | 지각·임금/피로·아이 돌봄, 인계 불발의 재연락, 반복 불이행에 따른 신뢰 변화. 확인되지 않은 수신·동의는 성공으로 처리하지 않는다 |
| 완료 기준 | 상대의 거절·연락 두절·재혼·사망, 같은 이름의 다른 자녀, 중간 저장/재개에서도 다른 부모/아이로 바뀌지 않고 비용·인계가 한 번만 적용된다 |

F-001의 시간·의무 구조가 먼저 필요하므로 이 사례를 완료했다고 표시하지 않는다. 성인 물질은 사용/비사용 선택과 관계·건강·지출을 연결하되, 관할·처방·노출 시간의 정밀 모델은 남은 요구다. 범죄/피해 확대에는 미성년자의 비선정적 보호·신고·지원·회복도 유지한다. 이번에는 실제 조달처·제조·투여 방법·사용량 안내를 추가하지 않는다.
