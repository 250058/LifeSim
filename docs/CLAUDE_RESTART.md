# Claude Code 작업 재개 인계서

사용자는 “클로드는 6~7시에 다시 작업 시작”한다고 알렸다. 재개 즉시 읽을 수 있도록 준비한 문서다. 이 표현의 시간대·오전/오후는 별도로 확정하지 않았으며, 새로운 예약이나 자동 실행을 설정한 기록은 아니다.

## 먼저 읽을 자료

1. main의 [현재 제품 계획](PLAN.md)과 [현실 재현 설계·누락 점검표](REALITY_MODEL.md).
2. [최신 안내](reviews/latest.md), [검토 범위와 미해결 상태](reviews/state.json), [05:55 코드 검토](reviews/2026-10-29T05-55-12Z.md).
3. [직업·범죄 요구 U-001/U-002](reviews/2026-10-29T06-16-05Z.md)와 [현실 재현 요구 U-003 전달 기록](reviews/2026-10-29T06-21-52Z.md).
4. [피드백 이슈 #1](https://github.com/250058/LifeSim/issues/1)의 새 댓글과 [PR #2](https://github.com/250058/LifeSim/pull/2)의 대화·리뷰.
5. [CLAUDE_REVIEW.md](../CLAUDE_REVIEW.md)의 응답·조기 리뷰 절차.

작업 브랜치의 문서가 오래됐으면 main의 최신 문서를 직접 읽거나 fetch해서 확인한다. 진행 중인 로컬 변경을 보존하고 강제 초기화·다른 작업자의 변경 덮어쓰기를 하지 않는다.

## 이번에 확정된 방향

- **U-003 현실을 가능한 한 1:1로 재현:** 64개 생활 영역의 사소한 행동·사건과 인과를 계속 확장한다. 18개 공통 시스템, 24개 검증 기준을 적용한다. 이 숫자는 설계 항목 수이지 구현된 상황 수가 아니다.
- **U-001 직업을 가능한 한 많이:** 직업 50종을 상한으로 삼지 않는다. 세부 직무·고용 형태·복수 일자리·실제 업무·진입과 전환을 연결한다.
- **U-002 범죄·피해·대응·회복을 폭넓게:** 묻지마폭행·성범죄·성희롱 등을 포함하되, 추상적인 사건·상태와 인물별 대응·기관 처리·장기 결과를 구현한다. 성희롱의 형사·민사·징계 판단은 구분한다.
- 자유로운 행동 조합, 거절·연기·중단·우회, 독립 NPC, 작은 사건의 장기 인과를 우선한다. 성인 술·담배·약물은 비사용·사용·중단·치료가 연결되며 성인 전환이 사용 이력을 만들지 않는다.
- 작성한 규칙, 의미 있는 상황 조합, 전체 생애 경로, 실제 관측 다양성과 반복률을 따로 보고한다. 생성된 이름·문장·ID 수만으로 수조 상황 구현을 주장하지 않는다.

## 현재 증거와 아직 남은 범위

06:33:17 UTC 확인 기준 main은 `87f5d2d8724001e5e564615bb3831bc41427d7e8`, 작업 브랜치와 PR #2의 head는 `66b55217daf986621143d3107fcff0a3e75f469a`다. main에는 이 인계서를 포함하는 새 문서 커밋이 추가될 예정이다. 재개 때 실제 최신 head를 다시 확인한다.

`66b5521`은 05:55 회차에서 명시된 범위로 이미 검토했다. 빌드·테스트 22개·데이터 검증과 현실 모드 1,000명 시뮬레이션 결과는 그 보고서를 따른다. 사건 ID 4,510개와 직업 정의 20종은 당시 데이터 규모이며, 전체 현실성·모바일·저장 버전 이전의 완료 증거가 아니다.

R-001~R-017의 상태를 그대로 이어받는다. R-005는 부분 해결이고 전체 기준 검토는 아직 남아 있다. Claude가 R-001~R-013을 수용한 기록과 실제 수정 완료는 별개다. 새 설계 문서로 기존 결함을 닫지 않는다.

PR #2는 새로 확인됐지만 head는 같으며, 확인 당시 댓글·리뷰·인라인 리뷰 댓글은 모두 0개다. PR 본문의 “사건 123개” 등 범위를 최신 구현과 실제 검증에 맞게 갱신하고, 생성 카드 수와 의미 상황 수를 구분한다. PR 생성만으로 리뷰 요청·접수·완료를 기록하지 않는다.

## 재개 후 우선할 작업 5개

1. **기존 오류의 작은 수정 묶음.** P1 R-006의 후계자 나이·관계 사실을 먼저 고치고 R-007의 평균 소득/연금 실질·명목 단위를 맞춘다. 각각 원래 재현 사례와 저장 후 사례로 확인한다.
2. **대상·시간·행동·예약 계약.** 인물/물건/기관 ID, 역할별 대상, 시간·단위, 즉시/지연 효과, 취소·대체·중복 방지를 정한다. R-011/R-012의 두 자녀·대상 사망 사례를 통과시키고 구버전 저장의 불명 사실을 임의로 채우지 않는다.
3. **실제 선택과 반복 가능한 관리.** R-008/R-009/R-013/R-014의 사용·비사용·노출, R-015/R-017의 치료 시작·유지·중단·재개·재발을 실제 상태에 연결한다. R-016의 실제 지급자/현금·표시액도 같은 거래 기준으로 정리한다.
4. **확률·기록·재현의 기반.** R-001~R-005와 R-010의 발생/표시 분리, 노출 단위·분모, 현실 모드, 사법 기록, 저장/콘텐츠 버전을 순서 있게 처리한다. 기존 검사 통과와 현실성 검증 완료를 구분한다.
5. **F-001의 끝까지 이어지는 일상 사슬.** 세탁 지연→물건/시간→대체·거절·약속→NPC 반응→비용/관계→저장·재개를 먼저 완성한다. 이어 F-002~F-005, 직업·범죄 및 생활 영역의 누락을 기존 ID에 매핑해 확장한다.

이 순서는 전체 세계 모델을 한 번에 갈아엎으라는 뜻이 아니다. 각 수정은 독립적으로 검토 가능한 범위로 나누고, 필요한 스키마·이전 정책과 반례를 함께 제시한다. 자료 조사와 콘텐츠 초안 작성은 진행할 수 있지만 실제 상태·행동 연결이 없는 초안을 구현 완료로 세지 않는다.

## 완료 보고에 남길 것

- 항목별 수용/일부 수용/보류/완료, 이유, 실제 변경 파일과 전체 SHA.
- 구현 수준: 설계 / 데이터 작성 / 엔진 연결 / 정적 확인 / 실행 확인 / 미확인.
- 새 누락은 REALITY_MODEL의 원장 필드로 기록하고 기존 R/F/사건 ID와 연결한다. 새로 추가한 이름만으로 별도 기능을 주장하지 않는다.
- 현재 package.json에 실제 있는 검증 명령 중 변경에 맞는 검사를 실행한다. 대상 SHA, 실행 결과·미실행 사유, 저장 재개·핵심 경계 사례를 남긴다.
- 준비되면 PR #2의 최신 head와 범위를 명시해 CLAUDE_REVIEW.md의 `@codex review` 절차를 따르고 이슈 #1에 요청 링크를 남긴다. 요청 접수·결과는 실제 반응으로 확인한다.

이번 Codex 작업은 계획·문서·전달이다. 이 문서가 게시됐다는 사실과 Claude 세션이 읽고 반영했다는 사실을 구분한다.
