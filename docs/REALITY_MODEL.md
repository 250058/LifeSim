## 1. 목표와 문서의 사용법

현실에 가능한 사소한 행동·상태·사건과 그 인과를 최대한 표현한다. 큰 성공·재난만이 아니라 아무 일 없는 시간, 유지·관리·기다림, 작은 즐거움, 불편, 실수, 수습, 포기, 회복도 구현 범위다. 직업은 계속 넓히며 묻지마폭행·성범죄·성희롱 등도 기존 승인 범위대로 다룬다. 사용자의 선택을 정해진 성공·결혼·취업 경로로 수렴시키지 않는다.

“현실 1:1”은 다음 축을 각각 평가한다. 모든 현실의 사실·물리 과정을 유한한 프로그램으로 완전히 열거했다고 선언할 수는 없다. 누락과 근사 범위를 공개하며 계속 확장하는 기준으로 사용한다.

## 3. 공통 세계 모델 — W-01~W-18

### W-01 동일한 존재와 복수 역할

Person, Household, Place, Organization, Object/Item, Service, Contract, Account, Case/Episode, Commitment/Task를 안정된 ID로 연결한다. 자녀·학생·친구·직원은 한 사람에게 동시에 붙을 수 있는 관계다. 생년·현재 생존·실제 관계 시작/종료는 바뀌지 않는 사실과 변화 이력으로 구분한다. 이름 변경·입양·재혼·이직·세대 전환에도 동일 인물을 유지한다. 인물 외에 집·물건·가게·학교·계약에도 정체성이 필요하다.

### W-02 단위와 달력

절대 시각, 지역 시각/시간대, 생일·연령, 날짜·요일·공휴일·계절·학기·근무일을 구분한다. 기간은 시작/종료/일시중지/실제 경과로 기록한다. 통화·가격 기준 연도·시간·거리·온도·재고 수량·위험률의 단위를 자료에 명시한다. 서로 다른 단위끼리 비교하거나 물가를 두 번 적용하지 않는다.

### W-03 여러 시간 규모의 진행

초·분이 중요한 응급/이동/대화, 일·주가 중요한 회복·일정, 월 단위 청구, 학기·연 단위 변화가 같은 시계를 사용한다. 연 단위 건너뛰기에도 마감·중간 개입·임금·치료·이미 정한 결과를 처리한다. 선택을 기다리는 중요한 일이 오면 멈추고, 작은 자동 변화는 기록한다. 화면 밖의 처리와 카드 표시 수는 실제 발생을 바꾸지 않는다.

### W-04 장소·이동·접근성

위치, 이동 수단·경로·소요 시간·운행 시간·요금·혼잡·지연·막차·주차·짐을 모델링한다. 장소는 집의 방·공용 공간, 교실·사업장·의료기관·거리·온라인 공간 등 기능을 가진다. 문 잠금·영업시간·예약·출입 자격·계단·엘리베이터·언어/감각/이동 접근성을 검사한다. 위치가 바뀌면 가능한 행동과 노출도 바뀐다.

### W-05 물건·시설·물리적 상태

소유·점유·공유·대여 권한, 위치, 수량, 상태, 오염·마모·충전·고장·유효기간·보관 조건·수리 이력을 가진다. 물건은 구매·사용·분실·양도·반환·폐기되는 같은 물건이다. 날씨·열·소리·충격·오염 등의 전달은 행동 결과에 필요한 해상도로 모델링한다. 시간·에너지·재료의 입력 없이 생산·수리되지 않게 한다. 물리 계산의 근사 범위를 표시하고, 선택의 결과가 달라지는 구간은 더 자세히 처리한다.

### W-06 조합 가능한 행동

행동은 행위자, 목적, 대상, 방식, 위치, 시작 시각, 예상 기간, 투입 자원, 조건, 타인의 응답, 취소/중단 정책으로 정의한다. 관찰·묻기·부탁·협상·거절·대기·이동·배우기·일하기·돌보기·구매·대여·수리·신청·상담 같은 공통 동사를 여러 영역에서 쓴다.

가능 여부와 성공률, 접근 비용, 실제 결과를 구분한다. 실패·부분 완료·예상 밖의 성공도 원인과 결과를 남긴다. 누르지 않은 행동을 수행했다고 쓰지 않는다. 위법 여부와 물리적 시도 가능성을 구분하고, 상대의 의사와 실제 제약을 처리한다. 자유 입력이 있으면 해석 결과를 확인 가능한 행동으로 바꾸고 엔진 판정으로 상태를 변경한다.

### W-07 자원 예약·동시성·중단

사람의 시간·주의·체력, 장소의 정원, 물건, 돈을 예약하고 실제 실행 때 다시 확인한다. 두 행동이 같은 시간/자원을 동시에 쓸 수 있는지, 양립 가능한 작업인지 구분한다. 취소 수수료·이미 지출한 재료·부분 진척·인수인계·대체 인력을 남긴다. 마감·대기열·선착순 경쟁은 안정된 처리 순서를 갖는다. 클릭 반복·재시도로 같은 결제나 결과가 두 번 생기지 않는다.

### W-08 사실·지식·기억·의사소통

실제 사실, 목격/전달된 정보, 소문, 추측, 틀린 기억, 비밀, 문서 증거와 신뢰도를 구분한다. NPC는 모르는 사실에 반응하지 않고 연락되지 않은 메시지를 읽은 것으로 처리하지 않는다. 대화의 시도·수신·읽음·이해·동의·약속을 분리한다. 관계별 정보 공개와 사생활, 감정 때문에 생기는 오해, 사과·정정·화해도 처리한다. 기억을 요약해도 후속 조건에 필요한 사실은 남긴다.

### W-09 독립적인 NPC와 기관

욕구·가치·기질·성격·기술·정보·현재 자원·일정·관계·목표에 따라 행동한다. 제안 거절, 먼저 연락, 이직·이사·관계 변화, 돌봄, 도움과 실수도 주인공의 버튼 없이 발생한다. NPC가 무조건 플레이어를 돕거나 불리하게 행동하지 않게 한다. 기관도 정원·예산·규정·처리시간·직원·민원·변경 이력이 있다. 통계적 갱신과 자세한 행동 계산을 섞을 때 이미 확정된 사실을 다시 뽑지 않는다.

### W-10 관계와 사회 구조

친밀·신뢰·호감·갈등·의존·권력·책임·공동 의무를 한 점수로 합치지 않는다. 양쪽의 인식은 다를 수 있고 관계망의 정보·추천·돌봄·배제 효과를 모델링한다. 가족, 동료, 학교, 이웃, 지역, 온라인 공동체와 서로 겹치는 관계를 보존한다. 특정 성별·출신·장애·성격 하나로 인생을 확정하지 않는다. 차별과 불평등도 구체적인 행위·제도·환경의 원인으로 다룬다.

### W-11 몸·마음·발달·치료

수면·피로·영양·갈증·배설·통증·감각·이동 능력·감염·부상·만성 질환·노화와 정신 상태를 구분한다. 증상, 확진 여부, 기능 제약과 치료 반응은 같지 않다. 진단/치료의 대상, 원인 노출, 접근성·비용·기간·순응/중단·재발·회복을 에피소드로 관리한다. 동일한 사건이 모두에게 같은 질환이나 평생 후유증을 주지 않는다. 성인 물질 사용은 비사용·거절·중단·치료와 같은 상태 계약을 쓴다. 의료 정보는 검증한 근거와 추상 게임 효과를 구분한다.

### W-12 경제·생산·거래

소득·현금·자산·부채·채권·지급 예정액·체납을 구분한다. 지급자/수혜자와 비용 부담자를 기록하고, 소비·재고·생산·물류·임금·세금·보험·이자·배상·복지를 연결한다. 계약과 거래는 가격·수량·기한·품질·반품·분쟁 상태를 가진다. 생활비는 가구 구성과 실제 소비/주거/지원에 반응한다. 실질/명목 금액, 개인/가구/회사 회계와 이전된 재산을 중복 계산하지 않는다.

### W-13 제도·자격·권리·절차

시대·지역·관할·신분·연령·자격별 규칙을 버전으로 관리한다. 신청 자격, 서류, 실제 승인, 갱신·만료, 이의 제기와 구제 절차를 구분한다. 형사·민사·행정·징계, 피해·신고·수사·기소·판결·집행을 별도 상태로 둔다. 규정과 실제 집행 지연·오류·지역 차이를 표현한다. 법률·제도 변경은 기존 계약·기대·이행 기한에 어떻게 적용되는지 정한다.

### W-14 확률·노출·공통 원인

사건별 모집단·기간·노출 단위·기본률·조건부 위험·불확실성·출처를 기록한다. 0은 0이며 발생 불가와 드문 발생을 구분한다. 인구당 연간 확률을 노출 한 번당 확률처럼 쓰지 않는다. 일정한 발생률 모형을 선택한 경우에만 기간 위험을 `1-exp(-rate×exposure)`처럼 변환하고 가정과 단위를 명시한다.

동일한 폭우·전염·경기 침체·사업장 환경은 여러 사람/사건의 공통 원인이 될 수 있다. 피해·실업·질병을 전부 독립 주사위로 만들지 않는다. 사건 추가로 기존 대상의 발생률이 뜻없이 희석되거나 빈도 상한 때문에 사실이 사라지지 않게 한다. 현실/드라마 보정은 버전과 함께 따로 기록한다.

### W-15 원인·후속 결과·사건 생애

사건 인스턴스 ID, 규칙 버전, 원인 ID, 참여자 ID, 대상, 시각, 당시 맥락, 선택과 결과를 연결한다. 후속 작업은 기한·유효 조건·대상 재검사·중복 방지 키·취소/연기 이유를 가진다. 사망·전학·이별·이직·사업장 폐쇄·법률 변경 시 같은 대상의 상태로 판단한다. 다른 가족이 조건에 맞는다고 대상을 바꾸지 않는다. 치료·관리·임금 청구·관계 회복처럼 반복되는 과정과 최초 한 번의 사실을 구분한다.

### W-16 시작 조건·세대·세계 역사

시작 연도·지역·가구·경제 상태·부모/보호자·기존 관계·사회 환경의 상관관계를 반영한다. 알려진 과거와 모순되지 않는 범위에서 배경을 생성하고, 자료 부족한 부분을 임의의 확정 사실로 바꾸지 않는다. 전환한 자녀의 생년·건강·관계·재산·채무·경력·지원 자격·예약 결과를 이어 받는다. 입양·재혼·비혼 가구·사별·가족 해체와 재구성도 하나의 가족 형태로 강제하지 않는다.

### W-17 저장·재현·실행 비용

엔진/콘텐츠/규칙/스키마 버전, 시드와 난수 스트림, 시작 설정, 행동 기록, 사건/대상 ID와 예약, 시간·원장·재고·기관 상태를 저장한다. 저장 스냅샷과 이후 기록, 무결성 확인, 원자적 저장/백업, 중단 복구, 마이그레이션과 지원하지 않는 버전의 처리를 정한다. 구버전에 없는 사실은 불명으로 남기며 현재 규칙으로 과거를 다시 뽑지 않는다.

시간마다 수조 조합을 전부 순회하지 않는다. 조건 색인·상태 변화 구독·예약 큐·인과적으로 관련된 후보로 평가한다. 먼 영역을 요약하는 규칙에는 상향 복원 시 보존할 사실·통계가 필요하다. 저장 크기·작업 시간·메모리·로드 시간은 실제 장치와 인물/기관/후보 규모로 측정한다. 화면 응답과 긴 시뮬레이션 처리를 분리하고 로딩 중 취소/진행 표시를 둔다.

### W-18 사용자가 읽고 조작하는 경험

현재 목표·일정·자원·관계·필수 기한, 가능한 행동과 이유를 이해할 수 있게 한다. 추천 선택지와 세부 조합 행동을 함께 둔다. 취소·보류·부분 완료를 조작할 수 있고, 비용·시간·상대 의사의 불확실성을 실제 알고 있는 범위에서 설명한다. 작은 사건은 일기·알림·요약으로 모아도 영향과 미결정을 지우지 않는다.

모바일 터치, 키보드, 화면낭독기, 글자 크기/대비, 한 손 조작, 긴 문장, 뒤로 가기, 자동 저장 실패·네트워크 끊김을 검증한다. 표현 강도·알림 밀도는 세계 상태와 분리한다. 설정으로 실제 사건 규칙까지 달라지는 경우 그 범위와 재현 설정을 명시한다. 플레이어의 진단·질문 화면에는 기술 구현 세부를 섞지 않고 게임 세계에서 유의미한 정보를 제공한다.

## 5. 사건 누락을 찾는 방법

매 새 영역에 다음 질문을 적용한다.

1. 누가 관찰자/행위자/대상/소유자/부담자/지원자인가. 동명이인·복수 역할·부재/사망도 구분했는가.
2. 언제 어디서 어떤 노출과 선행 조건으로 시작하는가. 단위·기한·반복 주기·관할은 무엇인가.
3. 시작 전 준비, 진행 중 선택, 거절/연기/부분 완료/중단/재시도, 타인에게 맡김이 있는가.
4. 즉시 변화, 내일·다음 달·몇 년 뒤 영향, 취소·오류 정정·회복은 무엇인가.
5. 본인이 모르는 사실이나 상대만 아는 정보를 서술·판정에 잘못 사용하지 않는가.
6. 물건·돈·시간·제도·관계·건강 중 빠진 연결이 있는가. 아무 변화가 없는 정상 결과도 가능한가.
7. 장소/사업장/관계/자격이 바뀌어도 같은 원인과 대상이 유지되는가.
8. 해당 기능이 실제 엔진에 없는 경우 “세계에서 불가능”이라고 처리하지 않았는가.
9. 현재 목록에 같은 의미의 규칙이 있는가. 명칭 추가인지 새로운 행동/결과/인과인지를 구분했는가.
10. 어떤 상태를 만들어야 도달하며, 실패/미발생이 정상인 경우와 저장 재개는 확인했는가.

교차 축은 나이/발달, 가구·동거, 지역·시대·제도, 자원/부채, 건강/기능, 직업/시간, 관계/권력, 장소/이동, 정보/기억, 날씨/세계 상태, 과거 원인, 선택·결과다. 전수 조합을 무조건 실행하기보다 제약을 반영한 두세 축 교차, 경계 조건, 고위험 누적 경로와 드문 사례를 우선 검증한다.

## 7. 콘텐츠·자료의 작성 계약

새 직업/행동/사건/제도 정의에는 다음 필드를 둔다. 아래 필드명은 설계 제안이며 현재 TypeScript 스키마가 이미 지원한다는 뜻이 아니다.

- 식별·버전: stableId, ruleVersion, contentVersion, category/domainIds, 기존 ID/대체 규칙.
- 대상·조건: 역할별 entityId 바인딩, 사전 조건, 위치/시대/관할, 필요한 정보/권한, 노출.
- 선택·판정: actor/target/method, 시간/재료/금전 비용, NPC 반응, 성공/부분/실패/취소와 각 효과.
- 결과·후속: 실제 변경분, 원인/에피소드, 발생/관측/선택 여부, 기한·재검사·중복 방지·취소 이유.
- 반복: 최초 사실과 반복 행동, 쿨다운/노출 기준, 상태 재진입, 회복·정정 경로.
- 근거: 출처 URL, 조사/기준 연도, 표 번호/정의, 모집단·분모·기간·단위, 추정/불확실성·적용 한계.
- 검증: 도달 fixture, 실제 선택 경로, 잘못 열린/막힌 반례, 보존 규칙, 저장 재개, 성능 표본.
- 집계: 작성 규칙인지 표현 변형인지, 의미 상황의 구분 축, 실제 관측/미관측과 중복 기준.

참고 자료는 통계청/KOSIS·한국표준직업분류, 고용/노동·임금/산재 통계, 보건/보험·질병·영양 조사, 교육·교통·주거·환경 자료, 경찰/검찰/법원 통계, 국가법령과 지방/기관 규정 등에서 정의를 확인한다. 이번 문서는 이 원표를 새로 대조한 통계 보고서가 아니다. 자료가 없으면 추정임을 기록하고 민감도 분석으로 영향 범위를 보여 준다. 보도된 극단 사례를 보통 사람의 매년 발생률로 쓰지 않는다.

## 8. 수천억~수조 상황의 집계와 실제 생성

작성 규칙 수, 생성된 카드 ID, 조건을 만족하는 의미 상황, 인생 경로, 표본에서 관측한 다양성, 체감 반복률을 각각 보고한다. 전체 경로가 많다는 이유로 단일 시점의 상황 수를 부풀리지 않는다.

의미 상황의 키는 참여자 역할/관계, 행동 가능성이 달라지는 자원 구간, 장소 기능·제도, 중요한 과거 원인, 사용자가 할 수 있는 행동 집합과 결과 규칙을 포함한다. 이름·시드·문장·인과 의미 없는 ID/소수점 차이는 키에서 제외한다. 구간 경계는 실제 선택/결과가 바뀌는 근거를 가진다.

보고에는 조합 축, 호환 조건, 상호 배타, 중복 제거 방식, 계산 범위, 근사/상하한과 도달 가능한 실행 예를 첨부한다. 이론적 곱셈은 느슨한 상한일 수 있고, 표본에서 많이 봤다는 사실도 전체 도달성 증명이 아니다. 작은 제한 세계에서는 가능한 상태/행동을 완전 탐색해 계산과 비교하고, 큰 세계는 제약 검사·경계 표본·대표 경로와 도달 증거를 함께 낸다.

생성은 상태에 맞는 후보를 찾고 역할·대상·맥락을 바인딩한 뒤 행동과 결과를 계산하는 방식으로 확장한다. 문장 생성이 새로운 사실을 마음대로 만들지 않게 한다. 저장은 모든 미래 조합 대신 현재 상태·규칙 버전·결정한 원인/결과와 재현 기록을 보존한다.

| V-20 자료 무결성 | 없는 참조/대상·서로 모순된 조건·영원히 닫힌 선택·단위 누락 탐지 |
| V-21 성능 | 장치/규모별 상태 진행·행동 지연·저장 크기/시간·로드·메모리 측정, 정확성 손실 기록 |
| V-22 모바일·접근성 | 작은 화면·터치·키보드·낭독·큰 글자·회전·긴 문장·저장 실패 조작 확인 |
| V-23 표현 정합성 | 설명한 효과가 실제 행동/확률/상태에 연결되고 결과 문구가 미선택 행동을 확정하지 않음 |
| V-24 범위 정직성 | 데이터 작성/엔진 연결/실행 확인을 구분하고 모든 현실을 구현했다는 근거 없는 완료 선언 없음 |

보존·변형 검사는 의미가 있는 것부터 쓴다. 예: 이름/문장만 바꾸면 물리 결과가 같아야 하고, 표시량을 바꿔도 이미 발생한 결과는 같아야 한다. 반대로 실제 기한·대상·노출·자격이 달라지면 해당 행동/결과가 달라져야 한다. 통계 검사는 동일 선택 정책의 여러 시드와 필요한 층별 표본을 사용한다. 본문을 그대로 확인하는 테스트만으로 완료를 대신하지 않는다.

## 10. 구현 순서와 누락 기록 운영

| 단계 | 먼저 완성할 것 | 완료 산출물 |
| --- | --- | --- |
| P0 현재 사실·오류 | 기존 R-006/007, 대상/예약·확률·사용/치료·지출 문제의 근거 있는 수정 | 수정 SHA·항목별 재현/회귀 확인·보류 이유 |
| P1 공통 계약 | 인물/대상 ID, 시간·단위, 행동/결과, 예약 생애, 거래 기록, 버전·저장 | 작은 API/데이터 예와 이전 저장 정책, 반례 검증 |
| P2 작은 연결 | F-001 한 사슬의 시작부터 중단·NPC 반응·장기 결과·저장까지 | 실제 플레이와 자동 재현 가능한 완결 경로 |
| P3 상호작용 확장 | F-002~F-005, 기관/계약·일정·정보, 반복 치료·직무 행동 | 여러 시스템 교차 검증과 단위/정체성 보존 |
| P4 내용의 폭 | 직업 U-001, 범죄 U-002, D-01~D-64의 기존/누락 목록과 우선 묶음 | 규칙/상황/관측 집계, 실제 데이터·근거·검수 |
| P5 규모와 현실성 | 독립 NPC/기관, 지역/시대·거시 원인, 빠른 진행과 성능 | 제한 세계 완전 탐색·큰 세계 표본·장치 벤치마크 |

콘텐츠 초안과 자료 조사는 기반 수정과 함께 진행할 수 있다. 미지원 상태를 요구하는 새 카드는 “작성됨”으로 남기고 연결/검증 완료와 구분한다. 일정은 완료 기준을 기준으로 나누며 한 번의 작업 재개에 전 범위를 끝냈다고 선언하지 않는다.

누락 원장에는 `gapId / domainIds / 구체 상황 / 기존 관련 ID / 필요한 상태·행동 / 현재 수준 / 의존 작업 / 우선 이유 / 근거 / 완료 사례 / 수정 SHA`를 남긴다. 매 검토에서 새 누락만 추가하고 해결은 구현과 검증으로 확인한다. 새 기능이 한 영역을 넓힐 때 다른 영역의 원인·자료·저장 요구를 빠뜨렸는지도 함께 확인한다.

이 문서는 닫힌 최종 목록이 아니다. 플레이 로그·자료·사용자 경험에서 발견한 사소한 일을 같은 구조로 계속 편입한다.
